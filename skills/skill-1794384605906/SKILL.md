# 例程交付先落盘再补发

适用：早报、巡检、复盘等定时任务，结果需要达到用户聊天。

## 输入
- 本轮要交付的完整正文
- 落盘路径（按日期区分的报告文件）
- 收件人：默认为该助手与用户的主对话
- 是否需要同时发原文语音（以用户已确认的要求为准）

## 步骤
1. 先把完整正文写入落盘文件；已有当天文件且内容完整则沿用，不要重新编一份。
2. 再把同一份完整正文发到约定聊天。
3. 若隔离运行无法发出或交接中断，主对话接手后必须立刻补发全文，不得只指路径或只说交接失败。
4. 补发前核对落盘文件与要发送的正文一致；用户已经拿到完整正文则不重复刷屏。
5. 若用户已要求「同时配原文语音」，在全文发出后，用同一份正文再发一条语音，不要改写成摘要。隔离运行发不出语音时，主对话补发这条语音。

## 验证
- 落盘文件存在且内容完整
- 用户聊天中出现同一份全文，不仅是「已跑完」的状态
- 若要求了语音：聊天里有覆盖原文的语音，不只是文字

## 常见失败
- 内容已生成但交接被中止，聊天里看不到主动推送
- 主对话只汇报卡点，没把全文补出去
- 没有落盘时，交接失败后内容丢失
- 要求了语音却只发了文字，或语音是摘要而不是原文

## 边界
- 不改变例程的内容、时间和收件人
- 不授权额外的外发或公开发布
- 用户没要求语音时，不主动加发
